HTTP · smoke test

Sabes que el endpoint está vivo antes de decirlo.

httpcheck pide una URL, compara el status con el esperado y reporta la latencia. Reintentos, timeout y JSON para que el último paso del pipeline sea una comprobación real.

Ver repositorio ↗

200 OK · el caso feliz. La URL respondió con el status esperado.

La señal

Status + latencia, sin abrir un dashboard

GET /health · 200 · 231ms

2xx / 3xx retry fail

Qué controla

Tres flags, suficiente

-expect

El status correcto

No siempre es 200. Un health check puede ser 204; una redirección, 302.

-retries

El arranque lento

Reintenta con intervalo configurable y muestra cuántos intentos hicieron falta.

-json

El pipeline

Un array de resultados con URL, status, latencia, intentos y error.

Uso

El último paso del deploy

Comprueba el health check después de desplegar y falla el job si el status no es el esperado.

httpcheck -retries 3 -timeout 2s https://example.com/health
